## Post ↔ campaign/label linkage & icons

- **Backend:** a **campaign = a planner folder**, a **label = plan label ids**. Post IDs resolved via `CampaignAnalyticsRepo` / `LabelAnalyticsRepo` (+ `PlansRepository::fetchPlansByFolderId` / `fetchPlansByLabels`). The new per-post endpoint carries each row's campaign/label ids from these.
- **Icons (FE):** there is **no image icon** — a campaign/label stores a `color` key (`color_1`…`color_20`). `CampaignAttachment.vue` / `LabelAttachment.vue` style a CSTU `<Icon>` via a color map (`getCampaignColor()` = solid bg/white text; `getLabelColor()` = tinted bg/colored text). The existing breakdown table `LableAndCampaignTable.vue` already renders a "Campaigns / Labels" column with these helpers — **reuse for the top-post cards, the Posts-tab columns, and the left filter dropdown** so all three match.

## Competitor landscape (brief)

Our scope is **table-stakes** and maps almost 1:1 to **Sprout Social's Tag Performance Report** (same metric set incl. engagement rate per impression, link clicks, video views). Buffer/Hootsuite/Publer/Loomly all offer a sortable post-level table; Buffer/Metricool have a top-posts module with a selectable ranking metric. Two under-served ideas worth noting (not required for v1):
- **Aggregate ↔ by-network toggle** (Sprout) — makes cross-network totals trustworthy.
- **Showing which campaign/label each post belongs to inside the table** — genuinely rare; we already get this for free via the Campaigns/Labels columns you asked for. A real differentiator.

**Cross-network aggregation caveat (Reach):** impressions/engagements/video views/link clicks are additive and safe to sum. **Reach is *not* safely additive** — it counts unique users, so summing across posts/networks double-counts (Metricool shows avg reach/post for this reason). Since you asked to match the current tiles (which sum), we'll **sum reach for consistency** — but I recommend the Reach tile tooltip say it's a **sum of per-post reach** (not de-duplicated unique reach). Also, networks that don't report a metric (e.g., LinkedIn reach) should show **"—", not 0**, and be excluded from that metric's total.
