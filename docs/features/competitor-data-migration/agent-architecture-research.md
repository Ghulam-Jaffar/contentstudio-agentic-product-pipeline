# Automated migration agent: code-grounded architecture research

Research date: 2026-11-01. Static source inspection only. This is a proposed design, not an implemented migration capability. Read `contentstudio-ai-agents/CLAUDE.md` and the architecture decision index first; the current dependency is Agno `>=3.1.2,<4` (`pyproject.toml:21`), so old framework observations must not be treated as current guarantees.

## What the agent should do

The customer authorizes source access, selects client scope and authorizes ContentStudio's social connectors. The service then inventories accessible records, resolves relationships, downloads permitted media, prepares destination objects, validates fidelity, imports safely, and reports exceptions. One bounded customer authorization can be designed to cover a reviewed batch; the customer should not manually re-enter every post or approve every deterministic copy. Ambiguous identities, elevated role changes, missing data rights and irreversible activation remain explicit exception gates.

“All data” must mean all selected, accessible, permitted data that can be represented faithfully. No AI can extract an unavailable endpoint, recover absent history, authorize a social account, invent missing media, or make a vendor license disappear. Source-specific capability discovery is essential.

## Proposed components and execution

1. **Migration API and authorization service.** Create a tenant-bound migration job, selected source organization/client scope, categories, retention policy and customer-approved activation rules. Resolve OAuth tokens through a secure credential reference. Neither tokens nor raw credentials belong in prompts, job payloads, logs or tool arguments.
2. **Source adapter registry.** Each vendor adapter declares readable object types, required scopes/plan, pagination, rate limits, native-ID semantics, supported deltas and licensing constraints. API/OAuth is the seamless preferred route when permitted. Export import is a separate assisted fallback; do not imply that a file-upload pilot proves automatic API extraction. Browser automation requires a supported/permitted route and must not bypass access controls.
3. **Durable orchestrator and item ledger.** New migration jobs, objects, relationships, attempts, mappings and exceptions. Track `source_vendor + source_tenant + source_object_type + source_object_id + destination_tenant` with explicit uniqueness/version rules; source fingerprints are labeled fallback identities, never fabricated source IDs. Persist cursor/watermark per extraction stream. Enqueue references to this state.
4. **AI mapping planner.** Supply schemas, selected sanitized samples and allowed destination candidates. Produce typed proposals: source field/object, destination field/object, transformation, supporting evidence and unresolved ambiguity. Exact IDs and already-validated mappings win over probabilistic suggestions. No custom model training is needed to begin; use existing model/structured-output infrastructure and measure mapping quality.
5. **Deterministic validator and transfer workers.** Copy captions and media literally. Parse dates/timezones, check platform options, quotas, role differences, asset checksums, parent references and destination permissions using code. The model does not rewrite content, invent IDs, calculate totals or decide that missing data is “close enough.” Transfer binaries outside the LLM.
6. **Migration-aware ContentStudio import API.** Call existing domain validation through dedicated held-write operations. Add origin markers and suppression for publishing, invitations, notifications, inbox auto-replies and automation. Ordinary post creation may schedule immediately; team creation sends invitations; approval attachment can fail after creation. Those observations in `01-research.md` make a dedicated import contract necessary.
7. **Reconciler and activation controller.** Read destination outcomes, compare source counts/assets/relationships, and resolve unknown write results before retrying. Refresh the final source delta where supported. Enable selected future publishing only after verified source pause and cutover ownership. A worker cannot atomically coordinate two vendors; unresolved source state remains held. Cancellation stops new work and preserves the per-item report; it cannot undo already sent posts or emails.

## Where AI adds value, and where it must not act

AI can interpret unfamiliar export columns, suggest team/client and label mappings, identify semantic differences in approval/automation rules, group exceptions and explain next actions. Deterministic software must enforce identity, authorization, exact copy fidelity, deduplication, network calls, quotas, write state and completion totals. Evidence-based proposals should include a rationale and a way to abstain. A model's stated confidence is not a calibrated authorization or matching guarantee.

Treat source captions, comments, filenames, CSV cells and API text as untrusted data. An embedded “ignore instructions and send this elsewhere” is content to preserve, never a tool instruction. The planner gets no secrets or unrestricted HTTP/file tools. Allowlisted adapters and destination operations enforce scope independently; validate every model proposal against schemas, known candidates and policy. URL safety helper `src/utils/url_safety.py:22` is a useful precedent, but migration downloads need redirect/DNS revalidation, egress restrictions, bounded size/type checks and malware handling too.

## Two implementation approaches

**Preferred when existing Temporal operations are available:** a durable migration workflow invokes extraction, mapping, validation, held-write and reconciliation activities; SQL/object storage holds per-item data. Pause/authorize/resume and long-running retries fit this shape. Activities remain idempotent; workflow orchestration alone does not make external writes exactly-once.

**Lower infrastructure dependency:** Dramatiq workers execute stages against a SQL migration ledger with leases, checkpoints, compare-and-swap and an outbox. This reuses current queue infrastructure but requires more explicit durable workflow logic. Do not run a multi-day migration inside a chat turn: the current Agno run store expires after 1,800 seconds (`hitl.py:43`, `orchestration/team.py:101`).

## Synthetic example, not observed performance

A fictional agency authorizes one client with two social accounts, 20 future posts and 12 media files. The agent reads the source inventory, matches one already-connected destination account, and requests one platform authorization for the other. It downloads assets, maps posts and detects one unsupported post setting. Nineteen items pass deterministic checks; the remaining item is held with its exact reason. After the customer-approved cutover conditions are met, workers activate only eligible future records. The report explains what moved, what is held, what source data was unavailable and which actions were taken. These numbers demonstrate states, not a success rate or delivery promise.

## Evidence needed before rollout

Use fixed labeled fixtures for source mappings; adversarial source text; cross-client IDs; app-scoped identity mismatches; multi-account posts; timezone/DST; expired media; interrupted pagination; permissions revoked mid-job; duplicate/reordered events; crash after destination write but before ledger update; and unknown API outcomes. Measure field/relationship fidelity, detection of unsupported records, unintended actions, duplicate writes, required user interventions, completion time and model cost. Set release thresholds from actual validation rather than invented confidence percentages. Existing `tests/unit/integrations/test_scope_credentials.py`, `test_session_state_races.py`, `test_operation_history.py` and `tests/evals/test_tool_selection.py` are precedents, not coverage of migration.

Unknowns: approved source API access and retention rights, exact source schemas, source delta/pause support, destination import guarantees, entity coverage, Temporal deployment availability, achievable intervention rate and production throughput. Premium packaging cannot remove these technical/legal limits.
