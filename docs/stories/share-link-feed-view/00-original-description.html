Description:

As a client reviewing posts through a share link, I want to see the shared posts as a feed, the way they'll look on each network, so that I can judge them as my followers will see them.

Feed is a new view only. Every link setting and client action works exactly as it does in List and Calendar today. Requested by Purplex Marketing, an agency moving from Vista, whose clients review posts in a feed today.

Workflow:

  1. Client opens the share link and, if asked, enters the password.

  2. Client sees the view switcher with Feed after the existing views, and picks Feed.

  3. Client scrolls the shared posts as a feed, each shown as it will look on its network.

  4. Client opens a post to see its comments, then approves, rejects or comments, as in List, when the link allows it.

  5. Client uses the status filters to see what's left.

Acceptance criteria:

View switcher

  • Feed shows in the share page's view switcher after the existing views, with the same icon as in the Planner.

  • The last view picked is remembered in this browser for that link.

Posts

  • Feed shows exactly the posts the link shares, as List and Calendar do, including new posts on links with "Share future updates" on.

  • Cards reuse the in-app Planner Feed card and network previews. No new card design.

  • The left action column (edit, duplicate, delete) and hover actions are hidden.

  • Each card shows the network, account, status, scheduled date and time, and comment count.

  • Posts load in pages as the client scrolls and never stop without saying so.

Same settings and actions as List and Calendar

  • Password, allow comments, allow approve or reject, external emails and Send for Approval (Anyone or Everyone) behave exactly as in List and Calendar.

  • When the link allows approval, the client can approve or reject from Feed, through the same post panel and the same name and email step as List.

  • When the link allows comments, the client can comment from Feed.

  • On view-only links, no approve, reject or comment controls show.

  • The All, Approved, Rejected and Commented filters work in Feed.

  • Bulk approve works in Feed wherever List offers it.

Impact in the app

  • A decision or comment made from Feed updates the post in ContentStudio exactly as one made from List: approval status, Planner, approval workflow and notifications.

  • A post rejected by a Send for Approval reviewer from Feed does not publish, as from List.

Screen sizes

  • Laptop and desktop: one centred feed column.

  • Phone width: to be designed by Tamim Rizvi. List already turns into cards on phones, so the design must show how Feed differs there (for example the full network preview against List's compact card).

  • At 375px, cards fit the width with no sideways scroll and no clipped preview (see CONT-4505).

Theming and language

  • White-label: links use the link's brand colours, as the rest of the share page does.

  • The Feed label follows the page language.

  • Client decisions from Feed show in the Planner exactly as decisions from List do.

  • Mobile app: share links made in the app (CONT-4092) open this same web page, so they get Feed too.
